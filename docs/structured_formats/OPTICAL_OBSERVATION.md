# Optical observations (`optical-observation-1`)

`optical-observation-1` is an immutable manifest for one hash-bound sensor
frame. It records the exact sensor/scene, pose, timing, seed, optional assembly
mount, and output arrays. It is equally valid for an offline render or a
physical sensor adapter. The authoritative parser is
`contraption.optics.schemas.ObservationArtifact`.

## Manifest fields

| Field | Required/default | Meaning |
|---|---|---|
| `format` | required | exactly `optical-observation-1` |
| `id` | required | nonempty trimmed observation identity |
| `sensor_id` | required | sensor identity |
| `sensor_sha256` | required | canonical `optical-sensor-1` digest, 64 lowercase hex |
| `scene_sha256` | required | canonical scene digest, 64 lowercase hex |
| `frame_index` | required | nonnegative integer |
| `requested_at_s` | required | nonnegative request time |
| `exposure_started_at_s` | required | nonnegative exposure-start time |
| `exposure_duration_s` | required | nonnegative duration |
| `ready_at_s` | required | nonnegative time when products became available |
| `pose` | required | exact sensor-to-world pose used for this frame |
| `seed` | required | nonnegative stochastic seed |
| `outputs` | required | nonempty outputs with unique names |
| `assembly_id` | absent | optional assembly closure identity |
| `assembly_sha256` | absent | optional exact assembly digest |
| `assembly_frame` | `world` | nonempty pose-frame identity |
| `mount_connector` | absent | optional exact `component.connector` binding |
| `mount_transform_sha256` | absent | optional digest of the resolved mount transform |
| `metadata` | `{}` | inert finite JSON |

Causal ordering is enforced:
`exposure_started_at_s >= requested_at_s` and
`ready_at_s >= exposure_started_at_s + exposure_duration_s`. When generated by
`from_arrays`, exposure duration comes from the sensor descriptor. The four
assembly-closure fields `assembly_id`, `assembly_sha256`, `mount_connector`,
and `mount_transform_sha256` are all absent for an unmounted laboratory/runtime
frame or all present for an assembly-bound frame; partial binding is invalid.
`mount_connector` then has the assembly-qualified form
`component.connector`. `assembly_frame` defaults to `world`.

`pose.transform_world_from_sensor_row_major` is a rigid homogeneous 4x4
row-major matrix. Sensor coordinates are +X right, +Y down, +Z forward; world is
right-handed +Z up/+X forward in metres.

## Output and content-reference records

Each output contains exactly:

| Field | Values |
|---|---|
| `name` | `rgb_linear`, `depth_m`, `segmentation`, or `uncertainty` |
| `dtype` | `int32` exactly for `segmentation`; `float32` exactly for every other product |
| `shape` | nonempty positive dimensions, at most 50,331,648 elements |
| `content` | exact canonical NPY sidecar reference |

A content reference has safe relative POSIX `uri`, nonempty `media_type`,
`sha256` as 64 lowercase hexadecimal digits without a prefix, and nonnegative
`byte_length`. The canonical factory stores Numpy `.npy` sidecars with media
type `application/vnd.numpy.npy`; it uses `int32` for segmentation and
`float32` for other products. All sidecars are little-endian, C-contiguous NPY
v1 or v2 arrays without object, structured, or subarray dtypes. Canonical
`from_arrays` requires exact sensor-sized
`[height,width,3]` RGB and `[height,width]` depth/segmentation/uncertainty.
It also requires the array-name set to equal the sensor's declared outputs and
refuses to overwrite an existing manifest or sidecar.

Loading with verification resolves every URI below the manifest directory,
checks byte count and SHA-256, parses the NPY header, and requires exact
little-endian dtype, C order, declared shape, and end-of-file framing.
`load_arrays` always uses `allow_pickle=False`. A manifest hash alone is not the
evidence closure; retain the verified sidecars too.

## Full inverse-problem solving

`OpticalInverseProblem(backend, scene, sensor, views, parameters, likelihoods,
constraints=())` solves a joint multi-view maximum-a-posteriori problem through
Torch autograd.
`InverseView.from_observation` verifies and loads this format. Available
targets are:

- scene targets listed in the optical-scene guide;
- `cameras.translation` with shape `[view,3]`;
- `cameras.rotation_vector` with shape `[view,3]`, an exponential-map delta;
- `sensor.focal_length` with shape `[fx,fy]`.
- `sensor.principal_point` with shape `[cx,cy]`.

Each inverse `ParameterSpec` has unique `name`, `target`, optional initial value
and Torch selector, transform `identity`/`positive`/`bounded`/`unit_vector`,
optional bounds, and optional prior. Positive uses softplus plus a lower bound;
bounded uses a sigmoid into required lower/upper bounds; unit-vector normalizes
the last dimension. Priors are `normal`, `lognormal`, `laplace`, or `uniform`.

Likelihood output is `rgb_linear`, `depth_m`, or `uncertainty`. Distribution is
`gaussian`, `student_t`, `huber`, or `poisson`; Poisson is RGB-only.
Likelihoods have positive scale/weight, Student-t degrees of freedom, Huber
delta, optional predicted-uncertainty scaling, and a nonnegative
`missing_observation_penalty` (default 25). Jointly finite samples form the
residual; a finite/non-finite visibility mismatch adds that penalty rather than
being silently masked. A comparison with neither finite samples nor a mismatch
fails.

A `DifferentiableConstraint(name, function, weight)` can add any positive-
weighted scalar differentiable penalty over the complete physical state and
named constrained parameters. It is a trusted host Python API, not serialized
DSL or metadata, and Luna must never author the callback.

`solve` supports Adam and L-BFGS, convergence tolerance, gradient clipping, and
optional Laplace covariance. The covariance is a symmetrized Hessian
pseudoinverse mapped through each constraint transform into physical parameter
coordinates; it is bounded to a configured raw-parameter count (default 256).
`InverseResult` retains constrained parameter arrays, predictions, loss history,
convergence, optional covariance, and `posterior_parameter_order`. That order
contains one flattened label per covariance row/column (for example `pose[0]`),
not merely one name per tensor. Visibility changes are
still discontinuous, so use multiple initializations/robust likelihoods and
held-out views. Posterior covariance is a local approximation, not global proof
of identifiability.

## Ownership boundary

Renderers and physical adapters create this record deterministically and attach
exact content hashes. Luna may declare PMDL artifact ports of type
`contraption/optical-observation@1` and reason about derived scalar behavior,
but it may not read image/depth sidecars, synthesize observations, run asset
calibration, or author this manifest.

For exact assembly-capture and reconstruction commands, outputs, and hash
closure, see [Offline optical workflows](./OPTICAL_WORKFLOWS.md).
